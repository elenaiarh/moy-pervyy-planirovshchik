### Готовый результат

Пользователь может создавать, редактировать, удалять и выполнять задачи. Рабочая задача имеет текстовое поле «Клиент», задачи «Я» и «Мы» клиента не имеют. Повторы доступны только `none`, `weekly`, `monthly`; редактирование повторяющейся задачи меняет только одно повторение.

Работают экраны:

- дашборд;
- день;
- неделя;
- месяц;
- модальное окно задачи.

В календарях видны категории «Рабочая», «Я», «Мы», выполненные задачи, просрочки, активные задачи и блоки «Воздух». В месяце не обрезаются кружки и счётчики.

## Шаг 4. Реализовать напоминания, откладывание и перенос задач

Статус: сделано.

### Готовый результат

Пользователь может включить напоминание для задачи, выбрать дату и время, получить локальное браузерное уведомление или внутренний тост. В интерфейсе есть честное предупреждение: напоминания надёжнее всего работают, пока АССИЯ открыта в браузере или PWA.

После срабатывания напоминание можно отложить:

- через 10 минут;
- через 1 час;
- завтра утром.

Работает перенос задач:

- drag-and-drop в неделе и месяце на desktop;
- на мобильном — через поле «Дата» в модальном окне редактирования задачи.

При перегрузе дня больше 5 задач приложение мягко предлагает перенести часть задач. Автоматически переносить без подтверждения нельзя.

### Автопроверка

- Проверить сохранение `reminderAt`.
- Проверить сброс `reminderDone` при изменении времени напоминания.
- Проверить срабатывание внутреннего тоста при наступлении времени напоминания.
- Проверить варианты откладывания и запись `snoozedUntil`.
- Проверить перенос обычной задачи на другую дату.
- Проверить перенос одного повторения повторяющейся задачи.
- Проверить предупреждение при добавлении шестой задачи на день.
- Проверить, что перенос не записывает данные в `localStorage` на каждое движение drag-события, а только после завершения действия.

### Ручная проверка

- Проверить, достаточно ли честно и спокойно звучит предупреждение о локальных напоминаниях.
- Проверить, удобно ли переносить задачу на телефоне через поле «Дата».
- Проверить, не раздражает ли предупреждение о перегрузе.

### История разработки

- В модальное окно задачи добавлено честное предупреждение о локальной природе напоминаний: они надёжнее всего работают, пока АССИЯ открыта в браузере или PWA.
- Добавлена валидация: если напоминание включено, но дата/время не выбраны, задача не сохраняется и показывается мягкая подсказка.
- Логика напоминаний теперь учитывает `snoozedUntil`: если напоминание отложено, следующее срабатывание проверяется по этому времени.
- После срабатывания напоминания показывается внутренняя панель «АССИЯ напоминает» с вариантами: «Через 10 минут», «Через 1 час», «Завтра утром», «Я увидела».
- При откладывании заполняется `snoozedUntil`, а `reminderDone` сбрасывается в `false`.
- При повторном срабатывании отложенного напоминания `snoozedUntil` очищается.
- Если время напоминания меняется при редактировании задачи, `reminderDone` сбрасывается, а старое отложенное состояние очищается.
- При перегрузе дня больше 5 задач и включённом чекбоксе заботы показывается панель с предложением перенести часть задач.
- В панели перегруза показывается список задач дня, задачи с фокусом «Не важно + Не срочно» подсвечиваются как хорошие кандидаты на перенос.
- Приложение предлагает ближайший день с меньшей нагрузкой; перенос выполняется только после клика пользователя по кнопке «Перенести».
- Добавлен перенос задач через drag-and-drop в недельной и месячной сетке.
- Для повторяющейся задачи перенос через drag-and-drop открывает подтверждение и применяет правило одного повторения: исходная серия получает исключение, а перенесённая задача создаётся как одиночная.
- Перенос обычной задачи меняет её `date` и переносит дату выполнения, если задача была выполнена на исходной дате.
- Запись в `localStorage` при переносе выполняется только после `drop` или подтверждения переноса повторяющейся задачи, не на `dragover`.
- Добавлены мобильные стили для панелей напоминаний, перегруза и подтверждения переноса; мобильная альтернатива переноса остаётся через поле «Дата» в модальном окне.

### Нюансы шага

- В браузерном тестовом runtime физический `cua.drag` не запускал HTML5 `dragstart/drop` у draggable-элементов, а DOM-eval не поддерживал создание `Event`/`DragEvent`. - Тексты заголовков панелей визуально отображаются в верхнем регистре из-за CSS-стиля; при автопроверке это учитывалось нормализацией регистра.
- Временный сервер на порту `5174` использовался только для чистой проверки и был остановлен после тестов.
- Удобство реального перетаскивания мышью в неделе/месяце и перенос на телефоне через поле «Дата» нужно проверить вручную.

## Шаг 5. Добавить PWA, тёмную тему и резервное копирование

Приложение поддерживает PWA:

- есть manifest;
- есть service worker;

- приложение можно установить на телефон;
- данные остаются в `localStorage`.
