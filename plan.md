# План реализации MVP «АССИЯ» по `tz.md`

## Шаг 1. Привести основу проекта и модель данных к ТЗ

Статус: сделано.

### Готовый результат

Проект остаётся локальной веб-страницей без backend и базы данных. Данные задач хранятся в `localStorage` по ключу `assiya.tasks.v1`. В коде есть единая нормализованная модель задачи с полями из ТЗ: `id`, `title`, `category`, `client`, `date`, `start`, `end`, `allDay`, `repeat`, `focus`, `care`, `reminderAt`, `reminderDone`, `snoozedUntil`, `completedDates`, `recurrenceExceptionDates`, `sourceTaskId`, `createdAt`.

Категории фиксированные: `work`, `self`, `together`. Старое значение `personal` мигрирует в `self`. Время окончания необязательно.

### Автопроверка

- Проверить синтаксис JS.
- Проверить, что новая задача сохраняется в `localStorage`.
- Проверить, что после перезагрузки задача восстанавливается.
- Проверить миграцию старой задачи с `category: "personal"` в `self`.
- Проверить, что задача без `end` сохраняется и не ломает расчёт расписания.
- Проверить, что задача с `end` раньше `start` не сохраняется и получает мягкую ошибку.

### Ручная проверка

- Проверить, понятно ли выглядят мягкие сообщения валидации.
- Проверить, не стало ли создание задачи визуально перегруженным.

### История разработки

- Добавлена полная нормализация задачи при загрузке из `localStorage` и для начальных демо-задач.
- Нормализованная задача теперь гарантированно содержит поля `snoozedUntil`, `recurrenceExceptionDates`, `sourceTaskId`, `reminderAt`, `reminderDone` и остальные поля из ТЗ.
- Старая категория `personal` мигрирует в `self`.
- Значение `end` сделано необязательным: больше нет автоподстановки `10:00` при сохранении обычной задачи.
- Для задачи без `end` активность, просрочка, подпись времени и расчёт «Воздуха» адаптированы под режим точки старта.
- Добавлена логическая валидация пустого названия и случая, когда `end` раньше `start`.

### Фактическая автопроверка

- `npm run check` прошёл без ошибок.
- Сервер `http://localhost:5173/` ответил `200 OK`.
- Через интерфейс создана тестовая задача без времени окончания.
- После перезагрузки страницы тестовая задача осталась видимой, значит сохранение и восстановление через браузерное хранилище работают.
- Через интерфейс проверена валидация: задача с `start = 15:00` и `end = 14:00` не сохранилась, модальное окно осталось открытым, показан мягкий текст ошибки.
- Тестовая задача удалена через интерфейс, после перезагрузки она исчезла.
- Статически проверено наличие миграции `personal → self` и новых полей модели.

### Нюансы шага

- В браузерной автопроверке нельзя было напрямую прочитать `localStorage` из-за ограничений тестового runtime, поэтому сохранение проверялось через пользовательское поведение: создание задачи, перезагрузка страницы и повторное отображение.
- В строке списка дня задача без `end` показывает старт в отдельной колонке времени. Формат «С 09:00» используется там, где задача отображается карточкой/подписью, а не в компактной строке.
- В рабочей папке уже есть не относящийся к шагу untracked-файл `.tz.md.swp`; он не трогался.

## Шаг 2. Реализовать создание, редактирование, выполнение и календарные представления

### Готовый результат

Пользователь может создавать, редактировать, удалять и выполнять задачи. Рабочая задача имеет текстовое поле «Клиент», задачи «Я» и «Мы» клиента не имеют. Повторы доступны только `none`, `weekly`, `monthly`; редактирование повторяющейся задачи меняет только одно повторение.

Работают экраны:

- дашборд;
- день;
- неделя;
- месяц;
- модальное окно задачи.

В календарях видны категории «Рабочая», «Я», «Мы», выполненные задачи, просрочки, активные задачи и блоки «Воздух». В месяце не обрезаются кружки и счётчики.

### Автопроверка

- Создать задачу каждой категории и проверить отображение в дне, неделе, месяце.
- Проверить, что поле клиента появляется только для рабочей задачи.
- Отметить задачу выполненной и проверить `completedDates`.
- Удалить задачу и проверить удаление из `localStorage`.
- Создать повторяющуюся задачу и проверить появление на нужных датах.
- Отредактировать одно повторение и проверить, что исходная серия не меняется.
- Проверить расчёт просрочки для задач с `end` и без `end`.
- Проверить, что блок «Воздух» появляется только для промежутков больше 30 минут.

### Ручная проверка

- Проверить, удобно ли читать день, неделю и месяц.
- Проверить, различимы ли цвета категорий.
- Проверить, не обрезаются ли элементы месяца на мобильной ширине.

## Шаг 3. Добавить фильтры, поиск и аналитику

### Готовый результат

Работают фильтры по:

- клиенту;
- дате;
- категории;
- статусу выполнения;
- просрочке;
- повтору;
- наличию напоминания;
- матрице фокуса.

Работает поиск по клиенту и дате. Есть аналитика по дню, неделе и месяцу: баланс «Рабочая / Я / Мы», выполненные и просроченные задачи, нагрузка по клиентам, самый активный клиент месяца, самые загруженные дни, процент выполнения.

Тяжёлая аналитика не пересчитывается на каждом рендере дашборда: дашборд считает только выбранный день, неделя — выбранную неделю, месяц — выбранный месяц, полная аналитика считается только при открытии аналитического блока.

### Автопроверка

- Проверить каждый фильтр отдельно.
- Проверить комбинацию нескольких фильтров.
- Проверить пустое состояние после фильтра без результатов.
- Проверить поиск по частичному совпадению клиента без учёта регистра.
- Проверить поиск по дате.
- Проверить расчёты аналитики на заранее заданном наборе задач.
- Проверить, что дашборд не запускает полный расчёт всей истории задач.

### Ручная проверка

- Проверить, не перегружает ли интерфейс количество фильтров.
- Проверить, понятно ли выглядят аналитические блоки и не создают ли давления.

## Шаг 4. Реализовать напоминания, откладывание и перенос задач

### Готовый результат

Пользователь может включить напоминание для задачи, выбрать дату и время, получить локальное браузерное уведомление или внутренний тост. В интерфейсе есть честное предупреждение: напоминания надёжнее всего работают, пока АССИЯ открыта в браузере или PWA.

После срабатывания напоминание можно отложить:

- через 10 минут;
- через 1 час;
- завтра утром.

Работает перенос задач:

- drag-and-drop в неделе и месяце на desktop;
- на мобильном — через поле «Дата» в модальном окне редактирования задачи.

При перегрузе дня больше 5 задач приложение мягко предлагает перенести часть задач. Автоматически переносить без подтверждения нельзя.

### Автопроверка

- Проверить сохранение `reminderAt`.
- Проверить сброс `reminderDone` при изменении времени напоминания.
- Проверить срабатывание внутреннего тоста при наступлении времени напоминания.
- Проверить варианты откладывания и запись `snoozedUntil`.
- Проверить перенос обычной задачи на другую дату.
- Проверить перенос одного повторения повторяющейся задачи.
- Проверить предупреждение при добавлении шестой задачи на день.
- Проверить, что перенос не записывает данные в `localStorage` на каждое движение drag-события, а только после завершения действия.

### Ручная проверка

- Проверить, достаточно ли честно и спокойно звучит предупреждение о локальных напоминаниях.
- Проверить, удобно ли переносить задачу на телефоне через поле «Дата».
- Проверить, не раздражает ли предупреждение о перегрузе.

## Шаг 5. Добавить PWA, тёмную тему и резервное копирование

### Готовый результат

Приложение поддерживает PWA:

- есть manifest;
- есть service worker;
- статические файлы кэшируются;
- приложение можно установить на телефон;
- данные остаются в `localStorage`.

Есть переключатель светлой и тёмной темы. Тема сохраняется в `localStorage` по ключу `assiya.theme.v1`. Тёмная тема сохраняет стиль АССИИ и не делает интерфейс резко чёрным.

Есть экспорт и импорт JSON-резервной копии:

- экспорт скачивает файл с `app`, `version`, `exportedAt`, `tasks`;
- импорт проверяет файл;
- импорт предлагает режим «заменить» или «объединить»;
- ошибочный файл не ломает текущие данные.

### Автопроверка

- Проверить наличие и валидность manifest.
- Проверить регистрацию service worker.
- Проверить, что основные статические файлы попадают в кэш.
- Проверить сохранение темы после перезагрузки.
- Проверить экспорт JSON и структуру файла.
- Проверить импорт корректного файла в режимах «заменить» и «объединить».
- Проверить импорт ошибочного файла без потери текущих данных.
- Проверить, что PWA не использует backend или внешнюю базу.

### Ручная проверка

- Проверить установку приложения на телефон.
- Проверить, нравится ли тёмная тема визуально.
- Проверить читаемость всех экранов в тёмной теме.
